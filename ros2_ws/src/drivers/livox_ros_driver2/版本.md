# Livox 驱动与 SDK 版本配套说明

最初记录：2026-10-29；PC／RDK 路径与操作说明核对：2026-11-05。

## 1. 必须使用的驱动包与 SDK

**本工程必须使用本目录中已经完成适配的 `livox_ros_driver2` 驱动包，并搭配下表指定的 Livox-SDK2 版本。**

| 项目 | 指定内容 |
| --- | --- |
| ROS 驱动包 | 本工程内的 `src/livox_ros_driver2`，即当前适配版 |
| 驱动源码版本宏 | `1.2.6`；本地适配内容也必须保留 |
| Livox-SDK2 版本 | **1.5.2** |
| SDK 固定提交 | **`c0796f04c143143899c87a773d9f6b7136453c0b`** |
| SDK 官方仓库 | <https://github.com/Livox-SDK/Livox-SDK2> |
| SDK 源码目录 | PC：`/home/fire/third_party/Livox-SDK2`；RDK：`/home/sunrise/third_party/Livox-SDK2` |
| SDK 安装前缀 | `/usr/local` |
| 配套雷达 | MID360、MID360S；通过启动配置选择其中一种 |
| PC 环境 | Ubuntu 24.04、ROS 2 Jazzy |
| RDK 现场环境 | Ubuntu 22.04.5、ROS 2 Humble；构建记录及未验证项见下文 |

SDK 的确切源码以固定提交为准，不能只拉取一个会随时间变化的 `master` 分支。该提交的官方源码版本宏为 `1.5.2`，可在[官方提交](https://github.com/Livox-SDK/Livox-SDK2/commit/c0796f04c143143899c87a773d9f6b7136453c0b)中核对。

驱动版本号和 SDK 版本号分别管理。仅找到一个同为 `1.2.6` 的上游驱动包，不足以替代本目录的适配版本。本包已包含：

- 普通 colcon 构建所需的 ROS 2 包布局，以及 Humble/Jazzy 的 rosidl typesupport 适配。
- MID360/MID360S 的设备类型处理及 SDK 版本条件编译。
- 收到点云数据后更新设备 Sampling 状态的运行修复。
- 通过 `config/msg_MID360.yaml` 选择型号的统一启动入口，以及相应 Python 运行依赖。

后续复制或迁移工程时，应完整保留本适配包及其配置，不要直接用上游下载的驱动覆盖该目录。

## 2. 仅在确需重装时卸载与更新 SDK

已经安装且能正常使用 Livox-SDK2 1.5.2 时，跳过本节；先用第 3 节查询版本，不要把以下删除命令当作启动前置步骤。确需重装时，操作前先用 `Ctrl+C` 停止正在运行的 Livox 驱动进程。SDK 安装在 `/usr/local`，由本机不同工作空间共享，更新后其他使用该 SDK 的工程也会受到影响。

下方 SDK 重装命令以 PC 为例；RDK 需将全部 `/home/fire/third_party` 替换为 `/home/sunrise/third_party`，安装前缀仍为 `/usr/local`。SDK 1.5.2 已在本机和 RDK 历史记录中核对，正常使用时无需重复执行重装步骤。

以下命令由操作者在终端中执行。每一步成功后再执行下一步；第一步会删除旧 SDK 的源码、构建目录和列出的安装文件。

### 第一步：卸载旧 SDK，并删除旧源码

```bash
cd /home/fire/third_party

sudo rm -f -- \
  /usr/local/include/livox_lidar_api.h \
  /usr/local/include/livox_lidar_def.h \
  /usr/local/include/livox_lidar_cfg.h \
  /usr/local/lib/liblivox_lidar_sdk_shared.so \
  /usr/local/lib/liblivox_lidar_sdk_static.a

rm -rf -- /home/fire/third_party/Livox-SDK2

sudo ldconfig
```

### 第二步：下载源码，并固定到指定提交

```bash
git clone https://github.com/Livox-SDK/Livox-SDK2.git /home/fire/third_party/Livox-SDK2

git -C /home/fire/third_party/Livox-SDK2 checkout --detach c0796f04c143143899c87a773d9f6b7136453c0b
```

### 第三步：编译、安装并刷新动态库缓存

```bash
cmake \
  -S /home/fire/third_party/Livox-SDK2 \
  -B /home/fire/third_party/Livox-SDK2/build \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX=/usr/local

cmake --build /home/fire/third_party/Livox-SDK2/build --parallel 4

sudo cmake --install /home/fire/third_party/Livox-SDK2/build

sudo ldconfig
```

## 3. 安装后核对版本

下面的命令直接查询已安装的 SDK 动态库：

```bash
python3 -c 'import ctypes as c; v=(c.c_int*3)(); c.CDLL("/usr/local/lib/liblivox_lidar_sdk_shared.so").GetLivoxLidarSdkVer(v); print("Livox-SDK2 %d.%d.%d" % tuple(v))'
```

预期输出：

```text
Livox-SDK2 1.5.2
```

SDK 更新后，需要重新编译本工程的适配驱动，使编译阶段使用新版头文件并启用相应设备分支。可在工作区根目录整体构建。PC 使用：

```bash
source /opt/ros/jazzy/setup.bash
cd /home/fire/Desktop/FAST_LIVO2_Ultra
CMAKE_BUILD_PARALLEL_LEVEL=2 MAKEFLAGS=-j2 colcon build --executor sequential
source /home/fire/Desktop/FAST_LIVO2_Ultra/install/setup.bash
```

RDK 已获取工程并安装依赖后使用：

```bash
source /opt/ros/humble/setup.bash
cd /home/sunrise/Desktop/FAST_LIVO2_Ultra
CMAKE_BUILD_PARALLEL_LEVEL=2 MAKEFLAGS=-j2 colcon build --executor sequential
source /home/sunrise/Desktop/FAST_LIVO2_Ultra/install/setup.bash
```

后续每个运行终端均加载所在设备的 ROS 和当前工程安装空间；RDK 不使用 PC 的 Jazzy／`/home/fire` 命令。

## 4. 配套型号配置与启动

`config/msg_MID360.yaml` 中的 `lidar_model` 可选 `mid360` 或 `mid360s`：

| 型号选择 | 对应设备 JSON | JSON 设备键 |
| --- | --- | --- |
| `mid360` | `config/MID360_config.json` | `MID360` |
| `mid360s` | `config/MID360s_config.json` | `Mid360s` |

统一启动命令：

```bash
ros2 launch livox_ros_driver2 msg_MID360_launch.py
```

默认读取安装目录中的 `config/msg_MID360.yaml`。修改源码目录中的 YAML 或设备 JSON 后，使用默认启动方式前应重新构建驱动包。驱动、建图和重定位均可省略手动配置路径，按默认入口启动；配置更改需先同步到安装目录，再重启相应节点。

当前仓库保持 PC 默认 `lidar_model: mid360`，两份设备 JSON 的主机地址均为 `192.168.2.50`。RDK 现场选 `mid360s`，将 `config/MID360s_config.json` 的 `host_net_info` 中 `host_ip` 设为板端实际地址，记录中的值为 `192.168.2.100`，雷达地址为 `192.168.2.3`。

两份设备 JSON 的 IP、主机网卡地址和端口需与实际连接一致。切换型号时先停止原驱动，再重新启动。本配置每次选择一种型号；两台雷达同时在线需要另外设计混合设备配置与话题分离。
