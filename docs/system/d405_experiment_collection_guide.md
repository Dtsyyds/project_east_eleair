# D405 焊缝巡迹实验数据采集操作说明

适用版本：2026-10-30 接入视觉巡迹操作后的当前项目。面向现场操作人员，用于采集后续离线标注、训练和评估所需的数据。

本手册对应当前 **Color + Depth** 巡迹入口、**D405 算法实验采集**专用方案；仅使用 D405 数据，供后续算法优化、离线标注和训练。D405 USB 停流问题尚未解决；本手册不是硬件稳定性或焊缝识别精度验收证明。功能实现与软件测试见[接入验证报告](../validation/20261030_vision_controls.md)。

## 一页操作顺序

**启动上位机 → 检查图像与存储 → 填写任务并预检 → 启动视觉巡迹 → 一键启动采集 → 保存代表性实验样本 → 一键停止并等待封存 → 停止视觉巡迹 → 核对、回放、备份 → 退出系统。**

| 操作 | 实际作用 | 不能混淆的地方 |
| --- | --- | --- |
| 启动视觉巡迹 | 启动 D405 算法，显示状态与结果，建立实验会话 | 不自动开始 MCAP 连续录制，不控制机器人 |
| 一键启动采集 | 开始既有 MCAP 连续录制 | 不自动启动视觉巡迹；必须单独确认巡迹状态 |
| 保存实验样本 | 保存下一组配对原始数据、已有标定和算法结果 | 不是保存当前网页截图，不自动生成真实标签 |
| 一键停止 | 停止连续采集并进入封存检查 | 不停止视觉巡迹；也不是机器人急停 |
| 停止视觉巡迹 | 停止算法进程，关闭实验样本写入器 | 不停止相机，不停止连续采集 |
| 启动终端 Ctrl+C | 退出整套上位机及其管理的进程 | 常规结束应先完成上面两项停止，再退出 |

## 1. 采集前准备

### 1.1 设备与存储

- 固定 D405 安装位置和姿态，记录实际工作距离、观察角度、样件与光照条件；距离未测量时填写“未测”，不要估作毫米真值。
- 检查 USB 连接、供电和固定情况；采集中不要改变线缆连接。
- 传感器只需 D405；还需要运行本项目的主机、可靠 USB 连接、数据盘、固定支架与适合采集的照明。无需工业相机、鱼眼、涡流、雷达或测厚设备。
- 数据盘默认 `/media/mcap_data`；当前配置最低剩余空间为 **5 GiB**。这只是软件门槛，不是足够完成一场采集的容量保证。
- 确认没有另一个程序独占相机，也没有独立运行的 D405 巡迹节点。

D405 专用方案要求以下四路原始图像均持续更新；双红外一并保留，便于后续离线比较与优化：

| 设备/流 | ROS 话题 |
| --- | --- |
| D405 彩色 | `/d405/camera/color/image_raw` |
| D405 深度 | `/d405/camera/depth/image_rect_raw` |
| D405 Infra1 | `/d405/camera/infra1/image_rect_raw` |
| D405 Infra2 | `/d405/camera/infra2/image_rect_raw` |

网页 D405 单个预览不能证明这四路 D405 原始流都正常。录制预检只检查这四路图像的新鲜度以及存储条件；仍应结合结束后的话题数量和回放检查持续性。

当前设备配置、序列号、分辨率和数据根以 [d405_experiment.yaml](../../config/communication/d405_experiment.yaml) 为准。更换相机或采集方案时由维护人员核对配置；不要为了通过预检随意删除必需话题。

### 1.2 为每组数据安排记录信息

建议开始前确定：操作者、样件编号、焊缝段编号、场景类别、实际光照、相机安装条件，以及本组要观察的变化。

任务命名示例：`20261030_A01_W03_正常光照_第01组`。这是命名示例，不是已有任务。

先采一组短流程样本，完整执行一次保存、停止、核对和回放，确认数据可用后再扩大采集量。短流程通过不代表长时间稳定性通过。

## 2. 启动上位机

在**连接设备的板端终端**执行：

```bash
cd /media/mcap_data/project_east_eleair_refactor
bash system_websocket/run_d405.sh
```

1. 保留此终端，不要关闭。
2. 使用终端打印的网页地址，在浏览器打开上位机；默认 HTTP 端口为 8080。
3. 若在另一台电脑打开网页，使用板端 IP，不要填写该电脑自己的 `127.0.0.1`。
4. 若提示“系统已经运行”，打开现有网页，不要重复启动第二套系统。
5. 若刚更新过代码，旧进程不会自动获得新后端功能。确认无采集/保存任务后，正常退出旧系统，再启动并刷新网页。

本入口明确加载 D405 专用配置，不启动工业相机、鱼眼、雷达或涡流驱动，也不读取工业相机参数。网页“采集 profile”必须显示 **D405 算法实验采集**；若显示其他方案，先停止现有任务并正常退出旧启动终端，再使用本入口启动。不要在录制中切换配置。

原 `bash system_websocket/run.sh` 仍是三相机入口，整机入口也保留。**仅点击“启动视觉巡迹”不会把三相机或整机录制自动切换为 D405 专用录制。** 本流程不需要手动再启动 RealSense SDK 采集器或第二个巡迹节点。

## 3. 检查界面与填写任务

先到“实时巡检”：

- 确认 WebSocket 已连接；运行模式不能是 `mock` 或 `simulation`。未知模式先核实，不把隔离测试画面当现场数据。
- D405 画面应更新；检查接收/显示 FPS 和“帧信息与诊断”，确认帧时间在变化，没有“画面已过期”。本方案工业相机、鱼眼未配置，不要求它们在线，也不能据此判定设备故障。
- 检查 SSD 挂载和剩余空间。
- 阅读告警。“状态待确认”表示依据不足，不表示已确认正常；“确认已读”不会解除故障。

再到“采集任务”：

| 输入项 | 填写建议 |
| --- | --- |
| 任务名称 | 日期、样件、焊缝段、场景、组次 |
| 罐体/样件 ID | 使用现场统一编号，避免不同样件共用一个 ID |
| 焊缝段 ID | 明确是哪一条焊缝、哪一段 |
| 采集 profile | 必须显示“D405 算法实验采集” |
| 操作员备注 | 操作者、光照、距离/角度、安装变化、场景类别及未测量项 |

点击 **执行预检**，等待“就绪”。若失败，按失败项排查，不能只看到一个相机正常就继续。预检只证明检查时的条件，不保证之后不会停流。

D405 专用方案不提供工业相机调参能力；原工业相机的“相机调参”也不是 D405 调参面板。

## 4. 启动视觉巡迹

当前 `run_d405.sh` 默认使用 `config/communication/d405_a.yaml`，巡迹加载
`config/d405/round1_a.yaml`：第一轮RGB模型、A原评分和原门槛，逐帧输出，不沿用上一帧轨迹。
旧局部对比/深度融合算法保留，可在后续正常启动时使用 `bash system_websocket/run_d405.sh --legacy`。
默认预览和启动巡迹均不自动录像；连续录像必须手动点击“一键启动采集”。
整机和三相机方案未指定算法配置时仍沿用原实验基线。
本次实际使用的参数以 `VISION-*/config.yaml` 快照为准；`VISION_2D` 仅表示二维候选有效。

1. 返回“实时巡检”，在右侧“巡迹结果”点击 **启动视觉巡迹** 一次。
2. 等待“启动中”变为运行中；A入口显示“A 原评分 · RGB”，旧入口显示“Color + Depth”。仅按钮点击或进程创建不算完成。
3. 展开“结果详情、观测与阈值”，记录本次 `VISION-*` 实验目录。
4. 观察巡迹状态、原因、新鲜度及 D405 叠加结果。默认仅用实验算法，不会驱动机器人。

| 巡迹状态 | 采集时怎么理解 |
| --- | --- |
| 二维视觉 / `VISION_2D` | 有二维结果，不代表三维或毫米定位有效 |
| 融合候选 / 几何候选 | 候选结果，需要后续验证，不能直接当真实标签 |
| 预测 / `PREDICTED` | 使用历史短期保持，不是当前帧的新测量 |
| 二维冲突 / `CONFLICT_2D` | 记录冲突原因，可保存为困难样本 |
| 巡迹丢失 / `LOST` | 没有可接受巡迹结果；原始数据仍可能有采集价值 |

`LOST` 不等同于画面没有焊缝；“无焊缝”负样本必须由人工根据真实场景确认。若是图像/深度停流、时间戳异常，应先处理输入问题，不将其混同为正常场景的算法漏检。

当前只在帧标识、源时间和尺寸等一致时叠加结果。D405 预览会暂存少量图像，收到延迟的算法结果后显示对应原帧：蓝线为左侧候选边线拟合，绿线为右侧候选边线拟合，红线为两侧拟合结果的二维中心线，画面下方显示同帧等待延迟。这不是机器人运动规划轨迹。点击“隐藏叠加”可切回原始预览；点击“显示叠加”恢复识别显示。无新鲜匹配结果时自动回到原始预览，LOST 或二维无效时清除线条。没有叠加时先确认视觉巡迹正在运行、相机仍出帧，再查看匹配和状态原因，不手工拖动线条来“对齐”。更新网页代码后使用 Ctrl+F5 刷新。

## 5. 开始连续录制

1. 回到“采集任务”，确认任务字段和采集方案正确。
2. 点击 **一键启动采集** 一次。
3. 等待任务明确进入“采集中”；确认时长、写入量在变化。
4. 记录本次 `WS-*` 批次 ID，与刚才的 `VISION-*` 会话一起填写到现场记录中。
5. 再返回“实时巡检”开始本组观察和样本保存。

此顺序让后续点击“保存实验样本”时能关联当前录制的 `run_id`。若未录制就保存样本，文件仍可保存，但 `collection_reference.json` 中的 `run_id` 为 null。

MCAP 仅订阅专用配置中的 14 个话题：D405 彩色、深度、Infra1、Infra2 原始图像及各自 camera_info（8 个），depth_to_color / depth_to_infra1 / depth_to_infra2 相机内部外参（3 个），以及已有巡迹结果、路径和诊断（3 个）。图像消息保留源时间戳和 frame_id，不保存浏览器压缩预览作为训练原图。工业相机、鱼眼、雷达、涡流、测厚、机器人状态和全局 TF/diagnostics 不在录制清单中。

`run.json` 保存实际选择的 `record_topics`，用于审计录制范围；任务名称、配置、算法输出和诊断作为 D405 实验元数据保留。某个话题被列入清单不代表它必然有数据。检查时仍须确认实际记录数量。没有启动巡迹就开始录制，不会凭空得到巡迹结果。

**网页断开、刷新或关闭不会作为正常停止操作。** 恢复连接后先查询、核对现有任务与巡迹状态，不重复点击开始。

## 6. 保存代表性实验样本

A入口为彩色逐帧模式，单帧样本不承诺同步深度；以下“配对输入”描述适用于旧融合入口。
需要完整彩色、深度、红外及标定流时，使用显式连续录制。

1. 让待采场景在相机视野中保持相对稳定。
2. 点击 **保存实验样本** 一次。
3. 等待“正在保存”结束，看到“实验样本已保存并通过文件校验；待人工标注”，并确认已保存计数增加。
4. 在结果详情中查看最近样本目录，记录该样本对应的真实场景。
5. 再切换下一个场景或观察条件。

操作约束：

- 保存的是请求之后的**下一组配对输入**，不是点击瞬间的浏览器画面。需要保持场景直到保存确认。
- 每次巡迹会话最多 **30 组**；两次被接受样本的源时间至少相隔 **1 秒**。不要快速连点，先等上一组结果。
- 排队或写入中不等于已保存；超时显示未知时，先查状态和目录，避免重复采样。
- 原始数据、实际收到的标定、算法结果一起保存；缺失标定保留为空，不自动补造。
- `result.json` 是算法输出；索引中的 `annotation=null` 才准确表示未人工标注。
- 不必只保存算法成功的帧。真实焊缝但 LOST、冲突、反光等失败场景同样有价值，应明确记录。

建议覆盖的场景，不是必须达到的固定样本数量：

| 场景 | 记录重点 |
| --- | --- |
| 清晰、居中的焊缝 | 基础正样本、边界是否清楚 |
| 焊缝偏左、偏右、进入和离开视野 | 位置变化与丢失过程 |
| 无焊缝的普通表面 | 人工确认的负样本 |
| 反光、阴影、表面纹理干扰 | 实际光照与干扰位置 |
| 遮挡、交叉或相邻结构 | 易误检结构和真实焊缝位置 |
| 不同实际距离或观察角度 | 记录测量值；未测就标明未测 |
| 真实焊缝但算法丢失/冲突 | 保留失败输入与算法原因 |

避免连续保存大量几乎相同的画面。若改变安装、光照或实验目的，建议结束当前组，建立新任务与会话。达到 30 组后也按正常结束步骤封存，再启动下一组；系统不会自动删除旧样本。

## 7. 正常结束一组采集

1. 停止提交新样本，等待正在保存的请求结束。
2. 点击采集栏的 **一键停止**。
3. 等待“停止中 → 校验/封存中 → 完整完成 / 未完整 / 失败”，记录最终状态。不能把停止按钮响应当成已经封存。
4. 点击 **停止视觉巡迹**，等待“已停止”，使实验样本写入器正常关闭。
5. 核对 `WS-*` 与 `VISION-*` 两个目录和现场记录；完成下面的检查与回放。
6. 当天全部结束后，在启动终端按 Ctrl+C 退出整套系统。

“完整完成”表示当前实现完成了录制关闭、MCAP 文件尾/话题等检查，**不代表焊缝精度、三维定位、标定或整个现场系统验收通过**，也不等于已经对全部 MCAP 内容做独立全量 SHA 校验。

如果停流保护已经自动停止录制，先记录本组状态；不要再次开始覆盖这次异常过程。保留 `incomplete` 批次用于诊断。

## 8. 核对数据、回放和备份

### 8.1 两类目录都要保留

默认数据根为 `/media/mcap_data`；如果配置改变，以页面和任务元数据中的实际路径为准。

```text
/media/mcap_data/
├── runs/WS-实际批次/
│   ├── run.json                    # 任务字段、录制状态、话题计数
│   ├── recorder.log                # 连续录制日志
│   └── bag/
│       ├── metadata.yaml
│       └── *.mcap                  # 所有分片都要保留
└── vision_experiments/VISION-实际会话/
    ├── session.json                # 来源、配置 SHA 和状态声明
    ├── config.yaml                 # 本组算法配置快照
    ├── node.log                    # 巡迹日志
    ├── index.json                  # 有成功样本后才生成
    └── samples/
        ├── result_manifest.json    # 写入器停止后的完成情况
        └── event_序号_源时间/
            ├── raw.npz             # 原始图像、深度、有效掩码和元数据
            ├── result.json         # 算法输出，不是人工标签
            ├── diagnostics.npz     # 可用诊断数组
            ├── metadata.json       # 文件清单、SHA、完成状态
            └── collection_reference.json
```

没有成功保存样本时可能没有 `index.json`；不能仅凭存在 `VISION-*` 文件夹就认为采样成功。运行中 `result_manifest.json` 尚未封存属于预期，应在停止巡迹之后检查。

### 8.2 结束后检查表

- [ ] 连续采集最终状态明确；若未完整，异常原因已记录。
- [ ] `run.json` 的 `collection_profile.id` 为 `d405_experiment`，`record_topics` 仅含 `/d405/camera/` 和 `/vision/d405_seam/` 下的清单话题。
- [ ] D405 四路图像、各自标定和三组内部外参实际话题数量非零，并与时长/预期数据量相符，不把只有一帧当持续采集成功。系统现有“完整完成”门禁检查四路图像，不代替对标定和实验结果完整性的人工检查。
- [ ] 计划录制巡迹结果时，核对 `/vision/d405_seam/result` 和诊断话题确实有消息。
- [ ] 有成功样本时，`index.json` 中条目数与本组已确认保存数量一致。
- [ ] 停止巡迹后 `samples/result_manifest.json` 的 `complete` 为 true；异常情况单独登记。
- [ ] 每个样本的 `raw.npz`、结果和元数据文件齐全。
- [ ] 保存期间有录制任务的样本，其 `collection_reference.json` 中 `run_id` 与现场记录一致。
- [ ] 光照、样件、焊缝位置、失败场景等人工记录能关联到对应样本。

### 8.3 用网页抽查连续记录

停止实时巡迹和连续采集后，进入“数据回放”：刷新批次，选择本次 `WS-*`，启动回放。检查开始、中间和结束附近的数据，查看 D405 彩色、深度伪彩及双红外是否持续更新；必要时使用暂停、继续和不同倍速。

回放页当前主要显示原始传感器记录。录进 MCAP 的巡迹结果话题不等于已经实现实时页同样的巡迹叠加回放；不要以“回放时没有叠加线”直接判定该话题没有录入，应查话题计数/记录。

### 8.4 可选：只读验证实验样本文件

由能使用终端的操作人员在板端执行。先替换 `VISION_DIR`，并且已经停止视觉巡迹。此命令不启动设备、不修改样本，仅校验索引、原始数据和样本文件 SHA；它不校验焊缝标签或测量精度。

```bash
cd /media/mcap_data/project_east_eleair_refactor
source deploy/env.sh s100p
VISION_DIR='/media/mcap_data/vision_experiments/VISION-替换为实际会话名'
python - "$VISION_DIR" <<'PY'
import hashlib
import json
import sys
from pathlib import Path
```

源目录保留原状；标注、筛选和训练产物另存到派生目录，不覆盖原始样本和记录。不要在完成核对与备份前删除失败批次。

## 9. 异常时按此处理

| 现象 | 处理 |
| --- | --- |
| 按钮提示板端未提供能力 | 确认新后端已构建并运行；无活动任务后正常重启系统、刷新网页。不要把灰色按钮当设备故障结论。 |
| 启动巡迹提示 D405 数据未就绪 | 检查彩色、深度新鲜度及停流提示；保留日志，不重复连点。 |
| 预检失败但 D405 能出图 | 先确认方案为“D405 算法实验采集”，再核对 D405 彩色、深度、双红外四路及磁盘，不能只检查一个预览。若仍要求工业相机/鱼眼，说明启动了其他方案。 |
| 巡迹 LOST，但图像/深度仍有效 | 记录实际焊缝是否存在及原因，可保存困难样本；不把 LOST 当“无焊缝”标签。 |
| 采集中画面过期或 D405 停流 | 查看任务是否自动停止/标记未完整；停止本组巡迹并保留异常记录，排查后另开新组。 |
| 保存被限流或达到 30 组 | 等上一请求结束；达到上限时正常封存本组，再启动新会话。 |
| 保存超时或结果未知 | 不立刻重试；核对计数、状态与目录。保留路径和日志，必要时由维护人员确认文件情况。 |
| 数据盘未挂载、空间不足或写盘失败 | 停止本组工作并记录状态，核实挂载/空间；不把缺失挂载点的普通目录当数据盘。 |
| 浏览器掉线 | 重新连接后先核对原任务和巡迹是否仍运行；不要以掉线为由重复开始。 |
| 提示已有独立巡迹节点 | 从该节点原启动终端正常结束；不要另开第二个节点或强杀不明进程。 |
| 停止巡迹未确认 | 按页面提示重试停止并保留 `node.log`；未确认前不拔盘、不宣称已经封存。 |
| 无法启动回放 | 先确认连续采集已结束、视觉巡迹已停止；两者与回放有互斥检查。 |

这里的停止操作都不是硬件急停。本手册不包含机器人运动指令，实验中的机械操作沿用现场既定操作规程。
