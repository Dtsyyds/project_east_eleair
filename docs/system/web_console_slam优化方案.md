## 1. 优化目标和边界

下一阶段的目标是让操作者看得懂状态、知道为何不能启动、能判断定位是否有效，并完成建图、停止保存和先验复用的现场闭环。优先完善状态与诊断，再优化页面和点云，最后扩展地图及历史会话管理。

- 功能主体继续放在 `apps/web_console_slam/`；独立后台不依赖巡检、底盘业务包。
- 保留 `8082` 独立 HTTP/WS 服务和 `8080` iframe 接入，不新增一套整机启动器，不重复启动驱动。
- 主要测试入口继续使用 `run_robot.sh --slam`；独立入口用于隔离故障和回归。
- 保留现有深色视觉风格和网关预览分流优化。近期不频繁断连是现场反馈，尚不能仅据此将原问题全部归因于无线网络。
- 不因界面优化改变算法参数、时钟检查、底盘控制、MCAP 录制或退出保存语义；算法调优单独评估。
- 优先复用已存在的接口和观测数据。新字段以兼容方式增加，具体协议变更在对应阶段落实。

## 3. P0：状态可信、故障可解释

### 3.1 分开显示页面、连接、任务和定位健康

页面顶端用简洁状态条显示以下内容，颜色之外保留明确文字：

| 状态维度 | 示例 | 判断来源 |
|---|---|---|
| 页面资源 | 正在加载、加载失败 | 页面启动及父页面就绪通知 |
| 后台连接 | 正在连接、已连接、重连中 | WebSocket 与状态包的新鲜度 |
| 任务生命周期 | 空闲、初始化中、运行中、停止中、保存中、已停止、失败 | 后台会话状态 |
| 定位健康 | 尚未就绪、有效、跟踪无效、里程计过期、未知 | 本次会话的新鲜观测 |
| 保存结果 | 未启用、等待结果、成功、无有效地图、失败、未确认 | 本次产物校验和退出结果 |

- 保留现有生命周期状态，新增独立健康信息，避免把瞬时跟踪失效直接改写成进程已经停止。
- 初始化显示已满足项、等待项、经过时间和超时上限，不使用没有算法依据的百分比进度。
- 断线或状态长时间未更新时，显示“任务状态未知”和最后确认时间，保留上次会话标识但标明信息已过期。
- 重连先查询后台，不重放启动请求；只有收到可用业务状态后才标记为可操作，连接成功本身不足以证明状态已同步。
- 跟踪无效或观测过期先告警，不新增自动重启算法、自动停车或自动切换模式行为。沿用已有进程异常和初始化超时处理。
- 新鲜度与持续时间优先使用单调时钟；传感器时间戳仍单独参与系统时钟偏差校验，不能混为同一指标。

### 3.2 把启动前检查做成可读结果

复用已有 `preflight` 操作，增加“检查启动条件”按钮。结果按检查项展示通过、失败、未知、检查时间和处理建议；点击启动时仍重新检查，不依赖过期结果。

检查范围：雷达/IMU 类型、发布者数量、新鲜度、时间戳推进与偏差、静止 IMU 样本、先验地图合法性、输出目录、依赖和冲突实例。静止加速度模只能作为单位及静止条件的合理性检查，不能声称自动识别了任意设备的真实单位。

现有接口返回错误列表，可先改善展示，再增加稳定的检查项标识、状态、简短说明和建议。普通界面优先显示可操作说明，原始话题、路径和技术信息放在可展开详情中。

运行期间显示的输入健康应来自轻量观测，不循环调用完整启动预检：完整预检包含目录写入探测，且冲突检查可能把本次运行实例识别为已存在任务。

### 3.3 连接和绘图异常隔离

- 为连接尝试和首个状态等待提供明确超时提示；重连使用有上限的退避与抖动，提供手动重试。
- 保留请求去重和会话标识校验；恢复连接只恢复状态和读取，不自动重试启动、停止等操作。
- 捕获 WebGL 创建、着色器编译和上下文丢失异常。绘图不可用时显示原因，配置、状态、日志和停止操作仍可用。
- 处理 `webglcontextlost` / `webglcontextrestored`，恢复时只重建显示资源，不影响后台算法。
- 父页面对资源加载失败只能给出有限诊断，不能仅凭超时断言是端口、网络或脚本错误；提供独立打开和重试入口。
- 保留唯一正确 MIME、缓存控制和精确 Origin 校验；增加资源与后台版本信息用于排查旧页面/旧进程，详情按需展开。

**P0 验收：** 输入未启动、输入过期、初始化等待、跟踪失效、服务未启动、断网重连、状态停止更新和 WebGL 失败均能明确区分；绘图故障不影响控制；重连不重复启动算法。真实 HTTP 头和 Chrome/Edge、Firefox 页面加载均需验证。

## 4. P1：布局与点云操作

### 4.1 让首屏围绕当前任务展开

沿用主界面的字体、色板、边框、按钮、徽标和间距。近期不引入大型前端框架或将独立页面绑定到主站资源服务。

- 顶部放置紧凑状态摘要；宽屏采用“配置与任务控制 + 点云主视图”，日志置于下方并可折叠。
- 窄屏保持单列，优先显示状态和启动/停止按钮，避免横向滚动；不把关键状态只放在悬浮提示里。
- 启动前展开配置；运行时可收起配置，但保留本次模式、先验和保存选项摘要。停止按钮在常见桌面尺寸中保持易于找到。
- 点云支持区域放大；折叠日志只是改变显示，不停止后台日志采集。运行状态变化不强制抢占焦点或滚动位置。
- 空闲、等待首帧、空帧、过期、解析失败、WebGL 不可用分别设计提示，避免黑色画布无法判断原因。
- 控件使用文字和图标共同表达状态，补齐键盘焦点、禁用原因和可读对比度。

这属于对原方案第 3 节纵向布局的下一阶段调整；交互能力、按钮尺寸和后台控制约束继续保留。

### 4.2 点云首先保证“看得稳、看得懂”

- 增加鼠标平移、适应当前点云、固定视角与可选自动跟随。当前点集变化时不默认持续重算视角中心和缩放，减少观察抖动。
- 增加坐标轴、米制参考网格与尺度说明；必须使用消息实际 frame_id，不把局部坐标系直接标为全局地图。
- 保留俯视和复位，增加点大小、高度着色/固定色等少量常用选项；不先堆叠复杂工具栏。
- 显示收到的预览帧率、帧龄、原始点数、预览点数与累计显示点数，明确“最近 N 帧预览”不等于完整地图。
- 轨迹和当前位置作为后续增强：需先确认里程计与点云坐标关系；没有明确同坐标系或经过验证的变换时不叠加。

### 4.3 按测量结果优化绘制与传输

- 记录解析、缓冲更新、绘制耗时与长时间内存趋势，区分设备、网络和浏览器瓶颈。
- 使用有界环形帧缓存和可复用 TypedArray；只在点集变化时更新点数据及包围盒，视角操作主要更新矩阵。
- 保留现有 5 Hz、2000 点/帧、最多 100 帧及 200000 点上限。先在现有限额下验证，再决定是否提供预览质量档位。
- 隐藏页面暂停绘制，必要时降低预览订阅或推送，但保持状态和控制可用；不能因此停止算法或日志。
- 不在没有瓶颈证据前改成二进制协议、压缩链路或工作线程。若后续需要，单独评估兼容和内存开销。

**P1 验收：** 建议覆盖 1366×768、1920×1080 和约 390px 窄屏；常见桌面首屏能看到关键任务状态、操作和点云区域。实际有 WebGL 的浏览器验证旋转、平移、缩放、点数上限、上下文恢复及切页。最大预览规模下记录 CPU、内存与操作响应，不能用无头浏览器的无 WebGL 截图代替渲染验收。

## 5. P2：日志、地图与历史会话

### 5.1 日志和诊断

- 增加当前已加载日志的关键词搜索、来源筛选和复制诊断摘要；明确筛选范围，避免把当前缓冲查询称为全量搜索。
- 错误摘要关联会话、时间、检查项和建议，原始日志继续完整保留；不凭不可靠的文本匹配自动推断算法成功。
- 支持导出指定会话的配置、状态和日志。若新增下载接口，只允许受控会话内的固定产物，限制大小和并发，防止拖慢控制链路。
- 将用户能理解的错误摘要和开发诊断分层展示，避免普通操作必须阅读大量终端日志。

### 5.2 保存结果和先验地图复用

- 停止后显示保存结果卡片，包括会话、模式、实际产物路径、大小、点数及校验结果；进程退出不等于保存成功。
- 地图列表增加只读元信息、更新时间和有效性；明确新地图输出目录与可选先验目录的区别。
- 如需“设为先验”，单独提供显式操作：校验来源、设置目标名称、检查重名和磁盘空间、完整写入后原子发布。不能自动覆盖原先验或改变正在运行的配置。
- 大地图元信息和校验异步执行并缓存，避免每次状态查询都读取完整 PCD；必须有失效条件和资源上限。
- 暂不加入任意路径上传、在线地图编辑、批量删除或自动清理。

### 5.3 历史会话

- 只读列出运行目录中的会话摘要，支持查看本次配置、结束原因、保存结果和日志。
- 历史记录和当前活动会话在界面上明确区分；历史查看不能将停止请求指向错误会话。
- 断电遗留记录显示“异常结束/结果未确认”，不自动补报保存成功，不自动恢复运行。
- 服务重启后不能仅凭历史记录宣称已接管原算法；会话恢复和进程归属沿用现有管理边界。

**P2 验收：** 正常保存、取消保存、无有效点、写盘失败、同名先验、损坏记录和断电遗留分别有正确表现；历史查询和导出不阻塞当前任务控制，不能越界读取文件。

## 7. 主要验收方式：有线网络下的整套测试

确认旧会话已正常结束，再执行：

```bash
cd /media/mcap_data/project_east_eleair_refactor
bash system_websocket/run_robot.sh --slam --plan
bash system_websocket/run_robot.sh --slam --check
bash system_websocket/run_robot.sh --slam
```

浏览器访问实际有线地址的 `8080`，进入“定位与建图”。本机默认有线地址示例为 `http://192.168.127.10:8080/`；其他地址按实际配置并传入对应 `--host`。无需同时启动独立 SLAM 或额外算法 launch。`--check` 仍只做软件与端口预检，实时输入由启动前检查验证。

建议验收顺序：

1. 记录设备、浏览器版本、访问地址、运行版本、会话目录和配置；先确认其他上位机页面工作正常。
2. 空闲时检查输入与页面状态；点击检查不启动算法，初次访问不自动建图。
3. 直接建图：静止初始化、查看状态与点云、切页、刷新、停止并验证地图产物。
4. 重定位建图：使用已验证且与现场匹配的先验，确认本次先验初始化、有效跟踪和扩图，再停止保存。
5. 在可控条件下注入断网、预览拥塞、跟踪失效、WebGL 不可用等情况；分别验证提示、恢复及不重复启动。
6. 建议先连续运行 30 分钟并记录资源趋势，再做至少 2 小时整机测试；这些是计划测试时长，不是已完成结果或可靠性承诺。
7. 退出整套入口，等待地图及录制收尾；核实无本次残留进程，原地图和基础配置未被覆盖。

验收记录至少包括：预期/实际状态、错误与恢复时间、重连次数及原因、命令响应耗时、预览帧龄、浏览器与设备 CPU/内存、地图校验结果。先建立有线基线，再比较无线；没有受控对照时不把所有断连归因于网络。

自动测试按改动范围执行，重点覆盖真实 HTTP 头、状态新鲜度、请求去重、绘图故障隔离、保存等待、地图路径边界和前端回归。原有整套故障隔离与独立启动能力应保持通过。真实输入、地图质量和实际浏览器表现需要现场记录，模拟测试不能替代。

## 8. 第一批建议落地内容

第一批控制在四项：**运行健康状态条、可读的启动前检查、初始化等待项、WebGL 异常隔离**。完成后，操作者应能直接回答：后台是否连接、任务是否运行、定位是否有效、当前卡在哪一步。随后再推进点云主视图和地图管理，避免页面变丰富而关键状态仍不清楚。
