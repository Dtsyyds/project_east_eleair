# D405 多候选距离排序离线 A/B：原门槛保持在选择之后

**原选择点上30/30帧存在多个候选，单候选0帧、无候选0帧。** 这里的候选严格指原动态规划终点的最优回溯路径，含同一路径的短前缀，不是30帧都存在多条独立焊缝。原实现没有“独立完整焊缝候选池”的定义。

**结论：本次距离优先规则整体明显退化，暂不采用。** 找对从17降至4，原17张正确帧中13张变为漏检。第23帧仅从错线变为无输出，没有找回真焊道；若只描述这一局部收益，应写作 **“单个错例改善，待独立验证”**，不能宣布整体提升。

## 运行前固定的协议

本机项目目录：`/media/mcap_data/project_east_eleair_refactor`；运行环境为原 `.runtime/s100p/d405_prototype_venv/bin/python`。复用第一轮 `d405_unet_round1_20261102/probabilities/01.npy` 至 `30.npy` 和原候选生成器，没有重新推理、训练、缩ROI或修改阈值。

本任务的配置、第一轮报告和标定记录中未找到独立标定的对准位置；在B选择和本次标签评分前写入 `protocol.json`，固定 **x0=W/2=320 px**，不是从人工线估计，也不是319.5 px。所有候选坐标均为原图640×480像素。

原代码 `continuous_rows` 对每个动态规划终点保留最优回溯路径，选择全局最高分路径，再调用 `candidate` 的覆盖率、拟合、连续性、宽度等门槛。本实验在同一选择点执行：

- A：原动态规划分数降序，平分时保持原扫描顺序。
- B：候选数大于1时，按候选自身测得行的中线x中位数到320的距离升序；距离相同按原分数降序，再保持原扫描顺序。无候选和单候选保持原行为。
- 没有使用上一轮的硬窗口；没有删除窗外候选，没有预先删短路径，没有合并候选，也没有把原门槛提前或增加失败后回退。
- 原ROI `[0.20,0.35,0.80,0.95]`、概率阈值0.55、覆盖率门槛0.55和其他参数全部保持不变。选中路径未通过原门槛就无输出。

30帧的候选逐条与上一轮暴露的原候选核对，坐标、分数、回溯内容和原排序均一致。全部A/B预测完成后才加载标签进行评分；标签不参与候选生成、中位数、x0或排序。
