# D405 长时间采集与停流定位（2026-11-02）

本轮目标是复现“画面过期”、保存故障前后原始数据，并验证修复。短时间恢复不作为
通过。当前没有完成 30 分钟无停流验收，不能声称根因已修复。

## 环境与证据

- D405：`352122271190`，固件 `5.17.0.10`；故障时仍为 USB 3.2 / 5000 Mbps。
- 主机：S100P，Linux `6.1.158-rt58-DR-4.0.5-2605072025-g7bb74b-gd7fa6f`。
- USB 控制器：ASMedia `1b21:3042`，PCI `0000:06:00.0`，相机路径 `2-2`。
- 工程 SDK：librealsense 2.58.4，原 V4L2 后端。
- 对照 RSUSB：同一源码编译，隔离在 `.runtime/s100p/native/rsusb-build/Release`，
  没有替换工程正式 SDK。普通用户缺少 USBFS 设备节点权限，仅试验时临时授权该节点。
- 采集均为四路 640×480 @ 15 fps，除明确注明的双路测试。
- 证据目录：`.runtime/s100p/validation/20261102_d405_longrun/`。
  `kernel_live.log` 保存内核事件，`xhci_errors.log` 保存独立 ftrace 实例的控制器事件。
  早期 `xhci_handle_transfer` 记录是普通传输 TRB，不应当全部解释为错误；
  `xhci_handle_event` 的 `USB Transaction Error` 才是本次使用的错误完成事件。

## 定位结论与限度

1. 画面过期与真实源停流一致，不能通过放宽网页超时解决。
2. 无网页、ROS、巡迹、录像时也可复现。RSUSB 绕开 UVC 视频驱动仍会失败，
   不支持把问题仅归因于网页缓存、ROS 转发、算法负载或 V4L2。
3. xHCI 在彩色停止前报告 `USB Transaction Error`（端点上下文 9，对应 IN 0x84），
   之后可能出现控制端点事务错误、端点重置或停流。原驱动对应出现 UVC `-71`。
   错误定位在设备与主机的 USB 传输链路，尚不能仅凭此区分相机固件、控制器、
   供电或物理链路质量。固定接线并不能证明这些因素已被排除。
4. 观察到的 PCI ASPM 已关闭；设备自动休眠计数在部分故障窗口不增加。
   端口 U1/U2 关闭的对照仍失败，不把省电策略当成已证实根因。

探针修正：最初在 `query_devices()` 返回对象上设置选项，不能保证作用于 pipeline
实际对象。修正版先 `config.resolve(pipeline)` 后设置，并在启动后读回。
SDK 自带录像还会注册通知回调、重新启用 error_polling；第三版在启动后再次关闭并
读回。因此早先“打印过 false”不代表所有 SDK 测试整个运行期都关闭了轮询。
工程 ROS 的通知回调安装后恢复选项逻辑已存在，MCAP 不走 SDK 录像接口。
本轮为 ROS 驱动新增启动后读取实际 GLOBAL_TIME / ERROR_POLLING 的日志，避免只依赖
ROS 参数值判断。`realsense2_camera` 重新编译通过；编译器有既有 overlay/RPATH 警告，
需要结合实际进程映射核实加载库。

12:24 对 D405 的 SuperSpeed 端口做受控禁用/启用：相机暂时退到 USB2 同伴端口，
这不是自发降速证据。随后 SDK hardware_reset，12:24:41 恢复 USB3，设备地址 32。
此操作不等于已证实 VBUS 断电。USBFS 与 U1/U2 试验设置均已恢复原值。

第三版探针后续采集为 `native_after_reset.db3` / `native_after_reset.log`，启动后实际
两个轮询标志均为 0。12:29:35 内核 UVC -71，随后四路不再出帧；没有 ROS/网页参与。
这组失败进一步说明，关闭轮询和设备复位都不能当作完整修复。未执行固件刷写，
也没有通过延长网页超时掩盖故障。D405 当前 5.17.0.10 在
[官方固件列表](https://dev.realsenseai.com/docs/firmware-releases-d400/)中支持 D405；
较新的 5.17.3.10 表格没有列出 D405，不能仅凭版本号更大盲目升级。

端口 U1/U2 为原值 `u1_u2`，端口启用。临时 USBFS 节点 ACL 随设备重新枚举消失。
主 SDK 未替换，没有新增系统启动规则。全部试验录制已关闭，保留约 12 GB 诊断证据。

实际相机进程映射确认加载 `.runtime/s100p/native/install/lib/librealsense2.so.2.58.4`，

## 长测工具

`tools/system/diagnose_d405_stability.py` 只订阅，不占有/复位相机：保存逐帧接收时间、
源时间戳、尺寸与布局检查，10 秒一份健康记录，最后输出 `summary.json`。
任一路超过 2 秒无帧、时间戳倒退/重复、布局异常或必要流缺失即判失败；
通过还要求完成指定时长、有效覆盖和实际帧率达到阈值。原始 MCAP 由正常采集服务负责。

工具用隔离 DDS 域验证了正常流通过和重复时间戳失败；真实停流也返回 `passed=false`。
不要把停止后的 `collection.stop` 成功返回值当成长测通过，应读取监测 summary。

参考：Linux [USB sysfs ABI](https://github.com/torvalds/linux/blob/v6.1/Documentation/ABI/testing/sysfs-bus-usb)
说明端口 `usb3_lpm_permit=0` 的意义；[USB 错误码说明](https://www.kernel.org/doc/html/v6.7/driver-api/usb/error-codes.html)
说明协议错误并不唯一指向某个硬件部件。
