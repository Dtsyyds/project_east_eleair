## 底盘与循迹扩展版

### 2026-11-10 融合版本

当前目录为 `web_console_chassis_tracking_1`。本次以他人修改后的界面为基础，
保留原有主题、D405/鱼眼/雷达/工业相机四宫格、R6 车体模型、点云操作和无模型图片采集，
补入遥控接管提示与控制禁用，以及电磁超声只读波形视图。原版目录未改动。

#### 遥控接管与人工恢复

底盘或探头收到新鲜的遥控接管反馈时，主页和独立底盘页显示相应提示。
关闭提示只表示知晓，不发送交还或恢复指令；同一接管过程不重复弹窗。
反馈过期或断线只代表未知，不当作交还。底盘接管期间，网页运动、启用和调参控件禁用，
停止控件仍可使用，待处理的视觉联动启动意图作废。探头单独接管不误停底盘循迹。

回中只停车。确认安全、CH1～CH5 持续回中至少 0.5 秒且至少 5 个有效帧后，
将 CH11 从低拨到高申请交还。STM32 还需确认在线、无故障、反馈新鲜及底盘停稳；
检查失败需要重新低→高，保持高位不能稍后自动交还。
失联造成的释放不能解锁网页。成功交还后仍须人工点击“启动循迹”，
或重新停止/启动视觉循迹；CH11、关闭提示和网页重连均不自动续跑。
实际接管、暂停和交还由配套 STM32 与 ROS 后台执行，更新网页不能替代固件和后台更新。

#### 电磁超声显示

“电磁超声”页通过原通信端口 9001 的固定只读路径 `/ws/emat`，
显示同帧原始 ADC、去基线信号、Hilbert 包络、底波候选及本帧使用的配置声速。
声速不是实时测量值，厚度明确标为候选；无数据或断线时清空曲线和数值。
新原始帧到来不会沿用上一帧的处理结果。可切换采样点下标和相对采样时间横轴，
每条预览最多 2048 点，完整数组仍在 ROS 话题。

后台需包含 EMAT 网关路径以及 `duct_robot_msgs`、`duct_robot_emat`、
`duct_robot_web_bridge`，数据来自 `/duct_robot/emat/waveform` 和
`/duct_robot/emat/processed_waveform`。`run_robot.sh` 默认不自动启动 EMAT 采集；
串口、声速和标定按 EMAT 功能包配置，初始化完成后显式采集。
该页面不创建控制租约、不发送采集或运动命令，原“一键测厚”后台协议不变。

也可以部署本目录内容到既有扩展版路径；更新后 Ctrl+F5 刷新。

### 视觉启停联动底盘与页面调参

仅本扩展版改变操作含义，原版 `web_console` 保持不变：

- “启动视觉巡迹”保留原视觉启动流程；等本次请求成功、视觉运行且收到新的有效观测，再调用底盘循迹启用服务。实车模式可能立即运动，先确认安全；预览模式只产生预览速度。
- “停止视觉巡迹”先请求停止底盘，然后执行原视觉停止（关闭算法/样本写入，不关闭相机/连续采集）。再次点击启动可重新开始，无需另敲启用服务。启动不成功或 15 秒内没有有效观测，明确提示未启用底盘，不自动重试。
- 底盘页“停止循迹”仍可单独暂停底盘；取消待处理的视觉联动启用。刷新、断线、迟到的旧响应和页面加载均不自动恢复运动。遥控优先权、硬件故障与超时保护不变。
- “底盘与循迹 → 循迹参数”：先停止循迹，点击“读取当前参数”，调整后点“应用参数（不启动）”。可设置巡航/最低速度、最大角速度、横向 Kp/Ki/Kd、方向 Kp、图像/接收超时及最低置信度。运行中（包括遥控接管等待恢复）拒绝应用；整组校验，失败不部分生效。
- 初次仅横向比例控制：保留横向 Kp，把 Ki、Kd 和方向 Kp 设为 0。页面显示的是 ROS 节点真实回读值，不是网页自行假定的默认值。参数仅当前进程有效，重启恢复原 YAML；没有增加自动持久化或关闭超时保护的接口。

RDK 需更新并重新编译 `duct_robot_tracking`、`duct_robot_web_bridge`；同时部署本扩展版网页。旧桥接无调参接口时按钮保持禁用。独立运行原相机脚本仍不启动底盘服务；联动需要使用整合入口。

扩展版脚本统一放在 `scripts/`，本地入口为 `bash scripts/run_robot.sh --real`。该脚本转发到现有启动链路，仍复用巡检工程 `system_websocket/run_robot.sh`，不另外维护一套端口和控制参数。可先执行 `bash scripts/run_robot.sh --plan`，仅检查启动计划，不启动设备。

默认同时支持网线 `http://192.168.127.10:8080/` 和无线 `http://192.168.1.148:8080/`，
无需指定 `--host`。网页按当前页面主机地址连接 9001；两种地址共用一套服务。
`--real` 才允许实际循迹输出，不加仍为预览；系统启动和自动连接不自动启用运动。

`scripts/run.sh` 保留原三相机入口，`scripts/run_d405.sh` 保留原 D405 入口（包含 `--candidate`、`--legacy` 参数），`scripts/run_robot.sh` 是新增的底盘与循迹整合入口。原位置的脚本和原版目录全部保留；这里的入口适配了目录路径并调用原脚本，不维护相互分叉的相机启动逻辑。三个入口按需选择，不要同时启动导致重复占用相机、串口或端口。非同级部署可设置 `INSPECTION_PROJECT_ROOT` 指向完整巡检工程。

当前目录命名为 `web_console_chassis_tracking`，以新下载的 `web_console` 为基础扩展；原版目录保持不动。保留相机、焊缝识别、采集、回放及雷达/位姿显示逻辑，新增独立的“底盘与循迹”页、探头控制、自动连接和模块录制清单显示。仍由 RDK 提供 `http://RDK_IP:8080/` 网页，相机、底盘与循迹的网页消息通过原 WebSocket 端口 9001 传输；ROS 内部 `/weld_tracking/error` 等话题保持不变。

此目录是网页扩展版，不能替代完整相机后台或 ROS 底盘工程。正式入口保留在巡检工程的 `system_websocket/run_robot.sh`：执行 `bash /实际路径/project_east_eleair_refactor/system_websocket/run_robot.sh --real --host RDK_IP`。网页目录放在该工程的 `apps/web_console_chassis_tracking` 或与工程同级，也可用 `--web-root /网页目录` 指定。底盘工作区由 `--chassis-workspace` 指定。先用 `--plan` 查看计划，不启动设备。不加 `--real` 只预览循迹；任何情况下，系统启动和网页自动连接都不自动启用车辆运动。

RDK 上需同步更新后台的 `tools/robot_session.py`、`tools/robot_gateway.py`、`system_websocket/run_robot.sh` 和此前的 ROS 网页桥接/循迹包。本目录的 `run_robot.sh` 仅兼容旧调用，转发到正式入口，不维护另一套启动逻辑。原版网页不被修改。缺少完整相机后台时会预检失败，不会把空占位文件当作可运行部署。

本文说明当前目录中的轻量离线操作台如何部署、连接和操作。当前交付由以下文件组成：

- `index.html`：操作台页面、布局和本地 SVG 图标。

- `console_core.js`：状态、新鲜度、帧匹配、能力门禁等公共逻辑。

当前页面已接入本工程 ROS 驱动与操作服务。工程根目录执行 `bash system_websocket/run.sh` 启动三相机上位机，浏览器访问 `http://<板端IP>:8080`；启动终端按 Ctrl+C 正常结束。设备及采集验收情况见 `docs/validation/`，界面可用不等同于所有设备持续采集通过。

## 工业相机调参

1. 在工业相机画面旁点击 **相机调参**，自动读取实际参数。
2. 修改曝光（ms）、模拟增益、RGB 增益、饱和度、Gamma 等参数；自动曝光启用时改用 AE 目标控制亮度。
3. 点击 **应用预览**，观察当前画面；可继续调整。
4. 满意后点击 **保存并沿用**，看到“当前参数已保存”即完成。下次启动上位机以及后续使用该工业相机的视觉任务会自动加载。

“保存并沿用”也会应用当前填写的参数，无需先点预览。保存按相机序列号隔离；分辨率和标定仍沿用任务配置。当前相机不支持自动白平衡，对应选项禁用；可调整 RGB 增益。采集和回放期间调参锁定，停止任务后再修改。失败或超时请点击“读取当前参数”确认结果后再操作。

## 1. 安全边界

1. 通过 HTTP 打开页面后沿用现有自动连接行为，连接后查询自检、任务、历史与回放状态；不会自动开始采集、测厚或保存。运动控制仍需能力、权限、实时状态及人工开关共同满足。
2. 旧协议只使用已有的自检和预览命令。板端没有通过 `capabilities` 明确声明的新功能，页面保持禁用。
3. 网页断线、刷新或关闭不应停止板端采集。重新连接后，页面只自动查询只读任务状态，不自动重发开始、停止、保存或运动命令。
4. “发送零速度”不是硬件急停。真实急停必须使用经过验收的独立硬件或板端接口。
5. 隔离 mock 不导入 ROS，也不会发布底盘 topic。mock 顶部会明确显示“模式 mock”。
6. Token 只保存在当前页面内存中；断开或连接重建时清除，不写入 `localStorage`、日志或导出文件。

## 2. 页面部署

### 2.1 现场部署

正式启动脚本直接提供本目录的静态页面。单独部署时，把下列八个文件放在同一目录：

```text
index.html
theme.css
theme.js
console.js
console_core.js
camera_tuning.js
replay.js
```

不要只替换其中一个文件，也不要创建 `index(1).html` 等并行页面。部署前后可用下面的命令核对文件是否一致：

```bash
sha256sum index.html theme.css theme.js console.js console_core.js camera_tuning.js replay.js
```

### 2.2 本机只读预览

在当前目录执行：

```bash
python3 -m http.server 8080 --bind 127.0.0.1 --directory apps/web_console
```

浏览器打开：

```text
http://127.0.0.1:8080/
```

页面不依赖 CDN 或公网资源。不要直接以 `file://` 打开；使用 HTTP 可避免浏览器对脚本和 WebSocket 的额外限制。

## 3. 连接板端

1. 打开“设备与调试”。
2. 在“板端地址”中填写完整 WebSocket 地址，例如 `ws://192.168.1.20:9001`。
3. 按需勾选“自动重连”。
4. 只有地址不包含 Token、用户名和密码时，才可勾选“记住非敏感地址”。
5. 点击“连接”。

也可以用查询参数指定初次自动连接的地址：

```text
http://127.0.0.1:8080/?ws=ws%3A%2F%2F192.168.1.20%3A9001
```

HTTPS 页面必须使用 `wss://`。浏览器会阻止 HTTPS 页面连接普通 `ws://`，操作台也会在发送前拒绝这种组合。

连接成功后页面先发送旧协议兼容的 `check`。如果板端随后在状态包中提供 `capabilities`，任务、事件、历史和底盘相关按钮才会按能力、权限及实时状态启用。顶部机器人身份默认是 `tank_inspection_robot`，板端能力信息提供有效 `robot_id` 后会更新来源。

## 4. 顶部常驻状态

桌面常规窗口顶部固定显示（窄屏或低矮窗口改为自然滚动）：

- 机器人身份及身份来源。
- WebSocket 连接状态。
- `live`、`mock`、`simulation` 或 `replay` 运行模式；未提供时显示“未知”。
- 当前 `run_id`。
- 采集状态。
- SSD 挂载和剩余空间。
- 当前最高级别活动告警。

“WebSocket 已连接”只代表传输通道存在，不表示设备、ROS 数据、算法、采集或正式验收正常。

## 5. 实时巡检

### 5.1 视频预览

鱼眼和 D405 面板分别显示：

- `receive FPS`：最近 2 秒内通过协议校验的预览包接收频率。
- `display FPS`：最近 2 秒内成功解码、尺寸校验并提交到画布的频率。
- 最后接收帧和当前显示帧各自的 `frame_id`、十进制字符串 `stamp_ns` 和本地时刻。
- 解码失败、尺寸不匹配、客户端待处理帧替代、隐藏页未解码、源时间乱序以及板端 `preview_dropped`。

页面只保留“一帧正在解码 + 一个最新待处理帧”。接收快于解码时，中间待处理帧会被最新帧替代，并记入“客户端替代”；不会创建无限解码任务。

图像内容按板端提供的 `content_type`、`image_type`、`semantic` 或 `source_encoding` 显示为“彩色”“Infra1”“深度伪彩”“融合叠加”等。页面不会仅凭 `camera_id=depth_camera` 把画面称为深度图。

深度 JPEG 仅供观察。没有原始深度和有效标定时，页面不显示毫米测距。分辨率相同也不表示图像和几何已对齐。

断线或超过该流的新鲜度后，最后一帧可以保留，但画面中央会覆盖“画面已过期”和最后显示时间。

### 5.2 巡迹结果

页面显示板端算法结果，不在浏览器重新实现巡迹。支持以下原始状态：

- `FUSED_CANDIDATE`：融合候选。
- `VISION_2D`：二维视觉有效。
- `GEOMETRY_CANDIDATE`：几何候选。
- `CONFLICT_2D`：二维冲突。
- `PREDICTED`：预测结果。
- `LOST`：巡迹丢失。

“候选”不会改名为“已确认焊缝”。二维有效、三维有效、身份确认和预测标志分别显示。

只有同时满足下列条件，边界和中线才会叠加到图像：

1. `robot_id`、来源、流、`frame_id` 和 `stamp_ns` 与当前显示帧完全一致。
2. 结果坐标明确为 `image_pixels`。
3. 结果声明的图像尺寸与显示帧一致。

否则页面显示“结果待匹配/已过期”“坐标不支持”或“尺寸不匹配”，不把最近收到的结果画到当前帧上。使用“隐藏叠加/显示叠加”查看原图与 overlay；画布使用原始像素坐标，CSS 缩放不改变几何坐标。

### 5.3 位姿与轨迹

位姿必须同时具备：

- 有限的 `x/y/z/angle`。
- `position_unit=m` 和 `angle_unit=rad`。
- 有效 `frame_id`。
- 十进制字符串形式的 `stamp_ns`。
- 独立、未过期的位姿记录。

轨迹是有界的轻量二维观察图，不传输全量点云。未完成资产坐标注册时，页面明确显示“未注册到罐体”，不显示 Course、Plate 或罐体缺陷位置。

### 5.4 涡流预览

只有板端真实提供 `channel_mean` 时才绘制通道均值。图表采用有界窗口，并以每个显示像素的 min/max 画线以保留均值序列中的尖峰。它不是原始波形，不影响原始录制；单位未提供时不标注 mm。

## 6. 采集任务

### 6.1 预检

1. 打开“采集任务”。
2. 填写任务名称、罐体/样件 ID、焊缝段 ID 和备注。
3. 从板端提供的 profile 列表中选择采集 profile。
4. 点击“执行预检”。

页面只提交业务字段，不提交目录或 shell 命令。`run_id` 和真实目录必须由板端生成并校验。

预检结果应由板端真实检查并返回，包括：挂载点、写权限、空间、必要设备和 topic、配置/标定版本、活动任务及 profile 条件。未配置设备应返回“未配置”，不能统一报成故障。挂载不存在时，板端必须阻止采集，不能在系统盘创建同名目录。

### 6.2 开始采集

预检状态为“就绪”且板端声明 `collection.start` 后，“开始采集”按钮启用。点击后页面显示：

- 请求 `accepted/running/completed/failed/unknown` 状态。
- 板端任务真实状态。
- `elapsed`、写入量、剩余空间。
- MCAP 和视频 writer 状态。
- 板端实际提供的队列、频率、丢帧和错误信息。

按钮点击后会立即锁定重复副作用请求。请求超时显示“结果未知”，页面先发送只读 `collection.status` 查询，不自动重发开始采集。

关闭预览不会停止录制；网页掉线也不应停止板端录制。

### 6.3 停止并封存

只有任务状态为“采集中”时，“停止并封存”按钮启用。点击后应依次观察：

```text
停止中 → 校验/封存中 → 完整完成 / 未完整 / 失败
```

页面分别呈现请求 ACK、writer 关闭、MCAP 有效、源文件 SHA 和算法/硬件验收状态。“ACK 已接收”或“进程已退出”不能单独显示为“完整完成”。没有算法或硬件验收证据时显示“未知”，不自动补成通过。

## 7. 事件标记与证据

打开“事件与数据”，选择事件类型并填写备注。支持：

- 焊缝丢失。
- 边界偏移。
- 深度异常。
- 疑似表面异常。
- 传感器异常。
- 自定义。

三个操作含义不同：

- “保存当前显示帧”：只有板端明确声明 `displayed_frame_cache=true` 且页面已有显示帧时可用。页面发送该帧的精确 `frame_ref`。
- “请求保存下一可用处理帧”：请求板端在下一可用处理帧上建立证据，不声称与当前画面相同。
- “添加事件标记”：保存人工事件和备注；如果存在当前显示帧，会附带其引用，但不把浏览器截图冒充板端原始证据。

`accepted` 只表示请求被接受；`queued/running` 表示仍在处理；只有板端返回 `complete`、文件清单和 hash 状态后才算证据完整。缺少原图、原始深度、overlay、几何或标定引用时，事件列表会显示缺失项。

“确认已读”只改变本页告警阅读状态，不表示故障恢复，也不会删除板端证据。

## 8. 历史任务与交接

板端声明 `history.list` 后，可在“事件与数据”中点击“刷新历史”。页面只显示板端登记索引返回的内容：

- `run_id` 和采集时间。
- 传感器、时长和大小。
- 封存、校验和硬件验收状态。
- 板端提供的下载服务说明、路径提示或交接命令。

板端绝对路径只作为提示，不会生成 PC 本地可点击文件链接。已封存源 run 应保持只读；后加备注和分析结果应作为派生内容引用源 run。

## 9. 设备与调试

物理设备和数据流分开展示：

- “物理设备”只列鱼眼、Mindvision、D405、涡流、EMAT、底盘和激光雷达。
- `eddy_raw`、`eddy_mean`、`lidar_pose` 等显示在“ROS 数据流与质量”，不会重复算作硬件。

每个对象独立记录更新时间。局部设备更新不会延长其他设备、位姿、巡迹、控制或存储状态的新鲜度。状态区分“未知、未配置、已禁用、活跃、已过期、设备错误、桥接断开”。新鲜度优先使用板端 `freshness_ms`、`expected_hz` 或 `expected_period_ms`；板端未提供时使用按对象类型区分的保守前端阈值。

“最近共享/关联回包”中：

- 带 `request_id` 的新协议回包可与本客户端请求关联。
- 不带 `request_id` 的旧 `response` 明确标为共享/未关联，不能作为某个按钮的独立 ACK。

清空页面日志只清理浏览器内最多 200 条的显示记录，不删除板端事件、任务或文件。

## 10. 底盘单次命令验证

本轮只保留受控的单次命令验证，不提供连续遥控或自动驾驶。必须同时满足：

1. WebSocket 已连接。
2. 板端声明 `chassis.move` 和 `chassis.stop`。
3. 当前会话具有权限。
4. 板端最新 `control.enabled=true` 且未过期。
5. 板端声明支持的自由度和每轴限速。
6. 操作员显式勾选“启用本页面命令测试”。

页面只显示板端声明的轴。例如板端只声明 `vx/wz`，`vy` 输入会隐藏。页面不会默认底盘支持 `vy`。

Token 如需使用，在发送时加入协议包，但在日志和导出中脱敏。回包中的“已接收”“ROS 已发布”和“硬件反馈”必须由板端分别提供；未知执行结果不能显示成功。

## 11. 掉线、隐藏页面与恢复

- 自动重连使用递增退避，最大等待 5 秒。
- 每次连接重建都会重置视频 FPS 和计数窗口，旧连接异步解码结果不会提交到新连接。
- 断开时清除 Token 和本页控制开关。
- 页面隐藏时保留最新一个待显示帧，不继续堆积解码；恢复后只处理最新帧。采集任务不受影响。
- `pagehide` 会关闭 WebSocket 和停止渲染定时器；从浏览器后退缓存恢复的 `pageshow` 会只重建一个定时器，并按自动重连设置恢复连接。
- 重连后只恢复任务状态等只读查询，不自动重发采集、停止、保存或运动操作。

浏览器与板端时钟没有经过可验证同步时，页面只报告本地“接收年龄”，不把源时间差称为端到端延迟。

## 14. 常见问题

### 按钮一直不可用

先查看按钮下方原因，再到“设备与调试 → 能力协商”核对板端是否声明对应 operation。仅连接成功或勾选本页开关不足以获得写盘或运动权限。

### 收包 FPS 正常但显示 FPS 为 0

查看视频面板计数。常见原因是 JPEG 损坏、回包尺寸与 JPEG 实际尺寸不一致、页面隐藏，或新连接已经替代旧连接。接收成功不等于成功显示。

### 看到旧图像

断线或流过期后页面保留最后一帧用于定位，但中央会显示“画面已过期”。元数据始终对应已提交画布的帧，不会使用最新回包给旧图贴时间和几何。

### 停止后为什么不是“完整完成”

停止 ACK、writer 退出、MCAP 有效、SHA 校验和算法/硬件验收是不同状态。板端没有完成或没有提供某一项时，页面保持“封存中”“未完整”“失败”或“未知”。

### 请求超时后能否再点一次

不要立即重复副作用操作。页面会把结果标成 `unknown` 并优先查询任务状态。确认板端没有执行后，再按现场规程决定是否重新操作。

### 清空日志是否会删除证据

不会。它只清理浏览器当前页的日志 DOM 和内存记录，不改变板端任务、事件或文件。

## 17. 视觉巡迹与实验样本

现场采集请按 [D405 焊缝巡迹实验数据采集操作说明](../../docs/system/d405_experiment_collection_guide.md) 执行，包含完整顺序、结束检查和记录模板。

在“实时巡检 → 巡迹结果”使用三个按钮：

1. **启动视觉巡迹**：沿用原数据盘和 D405 新鲜度检查，启动视觉节点并保存配置快照；视觉节点自身不发送运动指令。本扩展版另外等待确认及新有效帧后启用底盘循迹（见本文开头），所以实车模式可能运动。独立启动的视觉节点应先由其原启动终端停止，避免重复节点。
2. **保存实验样本**：请求下一组配对输入，保存原始图像、无损深度、源时间、已有标定、算法结果及诊断。它不是当前网页截图；缺失标定保持缺失，算法输出不作为人工标签。仅在文件和 SHA 校验完成、索引成功写入后显示已保存。沿用现有写入器每次巡迹最多 30 组、源时间间隔至少 1 秒的限制。
3. **停止视觉巡迹**：本扩展版额外请求停止底盘循迹，然后沿用原流程结束算法进程并关闭样本写入；不停止相机/连续采集，不是硬件急停。底盘停止未确认时页面明确警告。

连续数据仍使用顶部/采集任务页的“一键启动采集”和“一键停止”。MCAP 清单增加巡迹结果、三维路径和诊断话题；采集状态机不变。实时巡迹与历史回放互斥。页面断线不停止巡迹，重连只读取当前状态，不重发启动或保存操作。

数据保存于配置的数据盘下：

```text
vision_experiments/VISION-时间-唯一标识/
  session.json                    # 会话来源、配置 SHA；未标注、未硬件验收
  config.yaml                     # 本次实验配置快照
  node.log                        # 算法进程日志
  index.json                      # 成功保存后生成，兼容 d405_dataset_v1
  samples/
    result_manifest.json          # 样本写入器状态，正常停止后封存
    event_序号_源时间/
      raw.npz                     # 原始图像、深度、有效掩码及元数据
      result.json                 # 算法结果，不是人工标签
      diagnostics.npz             # 可用的诊断数组
      metadata.json               # 文件清单、SHA 与完成标志
      collection_reference.json   # 保存时正在录制的 run_id；未录制则为 null
```

“结果详情、观测与阈值”中显示本次实验目录和最近成功样本路径。索引中的样本保持 `split=unassigned`、`annotation=null`；后续使用既有离线标注/数据划分/训练流程，按会话划分避免同一采集泄漏到不同集合。本轮没有新增网页训练或自动标注。

若按钮显示“板端未提供视觉巡迹操作能力”，确认使用本轮构建后的操作服务，并以正常入口重新启动系统。D405 停流仍会阻止启动/保存，本功能不代表解决 USB 问题或通过焊缝精度验收。

点击“开始图片采集（无需模型）”，调整场景后点击“保存一组原图”，一批最多 30 组。结束时点击“停止图片采集”封存，随后进行网页人工标注和训练。采集与识别互斥，采集不依赖旧权重。详见 [采集与标注说明](../../docs/system/d405_experiment_collection_guide.md)。


## 定位与建图（随整机默认启动）

运行整机入口后，“定位与建图”页面自动加载同一设备 `8082` 的 SLAM 服务。服务初始为空闲状态，点击页面“启动”才运行算法。

```bash
bash system/run_robot.sh --plan
bash system/run_robot.sh --check
bash system/run_robot.sh
```

`system_websocket/run_robot.sh` 使用相同流程。已移除 `--slam` 开关和“独立打开”入口，不再提供单独启动 SLAM 的使用流程；`run_slam.sh` 仅作为整机启动器内部的服务启动脚本。默认支持网线 `192.168.127.10`、无线 `192.168.1.148`，ROS 域默认 `77`。访问其他地址时用可重复的 `--host 主机或IP`，SLAM 配置用 `--slam-config`。8082 固定保留给 SLAM；若旧服务占用此端口，先在其终端停止，再启动整套会话。

输入必须是 `/livox/lidar` 的 CustomMsg 和 `/livox/imu` 的米制 Imu，初始化时保持静止；默认整机模式提供这两路输入，算法需提前构建安装。两种建图模式及保存选项在启动后锁定，停止/Ctrl+C 会按本次选项等待地图保存；切页、刷新、断线不停止任务。SLAM 和 MCAP 分别控制，使用实时输入时不能向相同话题同时回放。

SLAM 未连接或任务失败不会中断其他页面。完整配置、输入启动方法、结果路径和现场验收步骤见 [SLAM 实现方案](../../docs/system/web_console_slam实现方案.md)，文件变更与软件测试见 [修改记录](../web_console_slam/修改.md)。

“连接与状态”提供重新连接与状态信息。“检查启动条件”按钮及可折叠结果位于“启动前配置”大框内的保存区域下方。启动日志位于启动/停止按钮所在框中，默认收起，点击标题展开。配置区显示后台配置决定的地图保存目录：直接建图为 `algorithm_root/PCD/priori`，重定位建图为 `algorithm_root/PCD/relocate`；每次任务使用独立子目录，任务开始后显示完整目录，结束后显示实际保存文件。

地图保存开关与只读保存目录位于同一个框内，启动后一起锁定。“建图可视化”的全屏按钮可放大整个点云面板，包含点云工具栏；点击“退出全屏”或按 Esc 返回。历史显示帧数默认 30、最高 100，每帧最多 2000 点、总计最多 20 万点，预览更新最高 5 Hz。100 帧在满速下约为最近 20 秒；流畅程度取决于浏览器设备，卡顿时减少帧数。该设置不改变后台 SLAM 和地图保存精度。

点云上方显示地图坐标系下的当前位置 XYZ（IMU 位置）及本次任务固定初值，单位米、三位小数，约每 0.5 秒刷新。直接建图初值为 `(0,0,0)`；重定位初值为 GICP 发布的初始 IMU 位置，在获得有效结果前显示等待。断线、过期或停止后保留的数值会明确标注；新任务清空上一轮数据，全屏下同样显示坐标。

默认整机启动链负责启动 Livox 驱动和 IMU 单位转换，供预检与算法订阅。SLAM 页面两种模式均调用 `relocalization/slam.launch.py`，统一管理 `fastlivo_mapping`、`teaser_gicp_node` 和 `transform_publisher`，不再启动雷达驱动。直接建图时配准节点停用，发布单位 `map → camera_init`；重定位时等待先验初始化成功后发布实际变换。“停止”结束整组算法任务，驱动继续为整机提供数据。任一核心节点退出时整组收尾，避免残留部分算法。详见 [算法修改记录](../../ros2_ws/src/functions/relocalization/修改.md)。

重定位初值被 FAST-LIVO 接受后，配准节点会停止计算和提交并保持空闲存活，等待任务统一停止；不会因配准成功而退出并打断建图。此时 FAST-LIVO 仍需完成 IMU 和先验地图初始化，请继续保持设备静止，等待页面显示运行就绪。2026-11-11 已修复旧版求解器成功退出导致整组提前停止的问题；安装新版算法后，下次从页面启动任务即生效。
